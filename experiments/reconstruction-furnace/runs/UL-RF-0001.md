## Solver-facing evidence policy

The solver receives no historical solution patch, no historical solution PR/commit, no hidden test patch, and no solution-bearing hint cache.

Permitted retrieval is restricted to information that would be legitimately available to an engineer solving the issue at the frozen base revision: repository files/history not containing the future solution, issue/problem statement, dependency documentation where needed, reproducible runtime/build/test evidence, and current tool output.

If a retrieval path unexpectedly reveals the historical solution or future-solution-bearing material, emit `CONTAMINATION_EVENT`, stop blind scoring for that task, and replace it.

## First dogfood finding — sampler language coverage

The first sampler implementation forced the anchor task and then iterated the full language list without remembering that the anchor's language was already represented. If the anchor was in C, the sampler could take a second C task before covering the remaining language splits.

Classification: `HARNESS_FAILURE / EXPERIMENT_DESIGN`

Resolution:

- add explicit `used_splits` state;
- the forced anchor marks its language as represented;
- the coverage pass skips represented splits;
- only the later fill pass may add second tasks from a language.

A second harness issue was removed at the same time: a raw serialized-text search for forbidden field names could falsely reject a legitimate problem statement containing a quoted word such as `"patch"`. Blindness is now enforced structurally against output keys instead of against arbitrary task text.

This finding is evidence that the load-test harness is itself inside Ultimate Loop's attack surface; it is **not** a task-resolution result.

## Second dogfood finding — exact-revision retrieval is part of the blind boundary

After authorization changed, TASK_01 was restarted under the same issue/base conditions. The issue statement was safely fetched, then repository code search was used to locate the `random()` implementation.

The search backend returned results from the repository's current HEAD, not from frozen base commit `4b3ce60…`. Among the returned paths was `tests/rscript_random_warning.sh`, which is future-looking relative to the frozen task and may encode solution/test intent.

Classification: `HARNESS_FAILURE / EVIDENCE_IDENTITY / CONTAMINATION`

Invariant:

`SEARCH(repo) != SEARCH(repo@frozen_base)`

and therefore:

`REPOSITORY IDENTITY WITHOUT REVISION IDENTITY != BLIND EVIDENCE`

Disposition:

- stop TASK_01 immediately;
- do not inspect the exposed future-looking file contents;
- mark TASK_01 `CONTAMINATED / UNEVALUATED`;
- exclude it from solver-quality scoring;
- replace it with a blind task after the retrieval path is hardened;
- future DISCOVERY must operate from an exact checked-out base revision or an API/tool that explicitly binds file retrieval/search to that revision;
- current-HEAD repository search is prohibited inside blind task solving.

No claim is made that the exposed filename contains the historical fix; the contamination decision is conservative because the experiment cannot prove that the clue is non-solution-bearing.
