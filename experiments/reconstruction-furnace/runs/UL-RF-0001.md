## Solver-facing evidence policy

The solver receives no historical solution patch, no historical solution PR/commit, no hidden test patch, and no solution-bearing hint cache.

Permitted retrieval is restricted to information that would be legitimately available to an engineer solving the issue at the frozen base revision: repository files/history not containing the future solution, issue/problem statement, dependency documentation where needed, reproducible runtime/build/test evidence, and current tool output.

If a retrieval path unexpectedly reveals the historical solution, emit `CONTAMINATION_EVENT`, stop blind scoring for that task, and replace it.

## First dogfood finding — sampler language coverage

The first sampler implementation forced the anchor task and then iterated the full language list without remembering that the anchor's language was already represented. If the anchor was in C, the sampler could take a second C task before covering the remaining language splits.

Classification: `HARNESS_FAILURE / EXPERIMENT_DESIGN`

Resolution:

- add explicit `used_splits` state;
- the forced anchor marks its language as represented;
- the coverage pass skips represented splits;
- only the later fill pass may add second tasks from a language.

A second harness issue was removed at the same time: a raw serialized-text search for forbidden field names could falsely reject a legitimate problem statement containing a quoted word such as `"patch"`. Blindness is now enforced structurally against output keys instead of against arbitrary task text.

This finding is evidence that the load-test harness is itself inside Ultimate Loop's attack surface; it is **not** a task-resolution result.
